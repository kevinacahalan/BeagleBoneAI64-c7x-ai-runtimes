# Hardware, Compiler, and Emulator Notes

Running log of verified TDA4VM (J721E) silicon behaviors, C7000 CGT quirks, and mismatches between TI's x86_64 C7000 Host Emulator (`libc70-host-emulation.a`) and live BeagleBone AI-64 hardware.

---

## Emulator vs. Silicon Mismatches

### 1. MMA C-bank Row Depth (`int32` accumulators)
- **Host Emulator (CGT 1.2.0.STS):** Wraps at **16 rows** per C bank when running `c7x_mma_probe_cbank` (`depth=32` overwrites row 0 with row 16).
- **TDA4VM Silicon:** Verified **bit-exact (0 mismatches)** at `depth = 16, 32, 48, 60, 63` rows per C bank! Each C bank physically holds **64 rows × 64 int32s = 16 KiB** (32 KiB total across banks 0 and 1).
- **8-bit `X_CRRSTPER` wrap at `depth = 64`:** With `X_CTYPE = INT32` and `X_XTYPE = INT32`, each C-bank row takes **4 paired `(__HWAXFER(0), __HWARCV(0))`** instructions (16 int32s = 64 bytes per XFER), and both `X_CRRSTPER` and `X_CSWPER` count **XFER instructions** (`rows * 4`), not rows. Since `X_CRRSTPER` is 8 bits wide (`0..255`), `64 * 4 = 256` wraps to `0` (resetting after 1 XFER). For exact `int32` readout, use `block_m <= 63` (e.g., `block_m = 60` or `63`, giving `X_CRRSTPER = 240` or `252`). Using `block_m = 60` instead of `16` gave an immediate **2.6× GEMM speedup** on silicon (`695 GOPS` in MSMC, `315 GOPS` in DDR).

### 2. MMA C-bank Release (`C_CWSWPER = 0xffffffff`)
- **Host Emulator:** Allows `__HWAXFER` to read C bank 0 even when `C_CWSWPER = 0xffffffff` (write FSM never switches out of C bank 0).
- **TDA4VM Silicon:** Returns garbage (`0x6a1b8804`) unless `C_CWSWPER` equals the tile op count so the write FSM switches to the alternate C bank before the X-stage reads the finished bank.

### 3. `cl7x 1.2.0.STS` 8-bit Vector Bitwise/Shift Miscompile (`uchar64`)
- **Host Emulator:** `uchar64` `&`, `^`, and `>>` compile via C++ templates and pass bit-exact.
- **TDA4VM Silicon (`cl7x 1.2.0.STS`):** Applying `&`, `^`, or `>>` to `uchar64` in C caused `cl7x` to spill 2,592 bytes of stack frame, run at `0.25 GB/s`, and produce incorrect W4A8 unpack results.
- **Fix:** Cast `uchar64` to `ulong8` (`__as_ulong8`), perform 64-bit native vector ops (`VANDD`, `VXORD`, `VSHRUD` with `0x0F0F0F0F0F0F0F0Full` / `0x0808080808080808ull`), then cast back with `__as_uchar64`. Zero stack spills, 100% bit-exact, **29.4× faster** (`11.27 GB/s` eq-INT8 on DDR).

### 4. Signed `int8` Output with ReLU (from parent repo)
- **Host Emulator:** Applies ReLU after saturation to `int8`, clamping negative values to `0`.
- **TDA4VM Silicon:** Leaves sums saturating below `-128` at `-128` when `X_XTYPE = INT8` + `X_ReLU = 1`.
- **Mitigation:** For quantized ReLU layers use `X_XTYPE = UINT8`; for transformer linear projections use exact `X_XTYPE = INT32` readout and apply per-channel float32 dequant + SiLU/GELU/RMSNorm on the C7x vector unit.

## Compiler & Hardware Gotchas

- **Lexical `HWAXFER` / `HWARCV` pairing:** `cl7x` enforces that every `__HWAXFER` has a lexically following `__HWARCV` in the same function before the next `__HWAXFER`. Keep `int32` row readout in a macro (`MMA_XFER_STORE_ROW_I32`), not a split helper function.
- **Host Emulation pointer casts:** In `libc70-host-emulation.a`, vector types (`char64`, `int16`, `ulong8`) are C++ objects, not raw 64-byte arrays. Always access memory through TI's vector pointer typedefs (`*(__uchar64_ptr)`, `*(__char64_ptr)`, `*(__int16_ptr)`, `*(__ulong8_ptr)`), never `*(char64 *)` or `memcpy(&vec)`.
- **J721E cache flush completion & double-`_mfence()` errata:** Writing `1` to `L1DWBINV` or `L2WBINV` is asynchronous — you **must** poll bit 0 until hardware clears it back to `0` (`regs.asm`) and then issue `__memory_fence(0x1)` twice (matching TI PDK `Cache_wait` errata). Without polling bit 0, the last 1–6 cache lines of a large write-back copy can still be in flight when Linux reads DDR.
- **ARM64 `/dev/mem` `O_SYNC` + `memset(..., 0, ...)` `SIGBUS`:** On Linux aarch64, `glibc`'s `memset` with fill byte `0` executes `DC ZVA`, which raises `SIGBUS` (alignment fault) on `O_SYNC` Device-nGnRnE `/dev/mem` mappings. Always use explicit volatile stores (`mmio_zero`) to zero `/dev/mem` regions on A72.
- **DRU0 (`0x6D000000`) direct-TR requires Type-9 TR (`TR9`), NOT Type-15 (`TR15`), and needs ZERO TI-SCI:** On J721E (`DRU_PID = 0x662c0900`), the low 16 bits of `DRU_CAPABILITIES` (`0x00000959000d0f20`) are `0x0F20` (bits 5, 8, 9, 10, 11 only — bit 15 is `0`!). Submitting a `TR15` (`type=15`) is silently dropped, whereas `TR9` (`type=9`, `CSL_UDMAP_TR_FLAGS_TYPE_4D_BLOCK_MOVE_REPACKING`, identical 64-byte layout) executes natively via a single 512-bit atomic `__ulong8` store to `CHATOMIC[0]` (`0x6D080000`) with zero TI-SCI or RTOS setup (`CSL_DRU_OWNER_DIRECT_TR = 0`).
- **DRU0 race-free completion wait & `TR_FLAGS_WAIT` gotcha:** Do NOT set `TR_FLAGS_WAIT` (bit 5) on a standalone TR — that bit pauses waiting for an external sync trigger. Polling `CHRT_STATUS_DET` immediately after `CHATOMIC` races the crossbar write latency. Submitting an ordered 8-byte `TR9` completion marker into the non-cacheable top of the L2 control page (`0x64800E00 → 0x64800F00`) right behind the payload TR gives 100% race-free, zero-DDR-traffic L2 polling (`10.92 GB/s` DDR→L2, `11.02 GB/s` DDR→MSMC, `56.00 GB/s` MSMC→L2, bit-exact 128 KiB round-trip).
- **DRU0 L2 SRAM ping-pong coherency, SE0/L1D snooping, & matrix size crossover:** Empirically verified on live TDA4VM silicon (`113/113` `test-backend-ops MUL_MAT` + `SmolLM2-135M` perplexity): C71x Streaming Engines (`SE0`/`SE1`) **snoop L1D** for CPU writes to L2 SRAM / MSMC / DDR (so CPU-written buffers in `stage_src0_to_l2`, `SOFT_MAX`, `ROPE`, `SET_ROWS`, and `mma_kernels.c` need zero L1D writeback before `SE0`/`SE1` reads). In contrast, **DRU0 DMA bypasses L1D**, so: (a) DRU0 DDR → L2 SRAM ping-pong buffers consumed exclusively via `SE0`/`SE1` require zero cache invalidation (keep `w_scales` in DDR for `m > 1` batched W4A8 prefill where CPU pointer loads read scales), and (b) any command that writes `l2_scratch` via CPU stores (`exec_matmul_f32`) issues one `ai64_l1d_wbinv_all()` on exit so stale dirty L1D lines cannot later evict over DRU0-fetched weights in a subsequent command of the same `EXEC_LIST`. On matrices `< 1 MiB`, direct 1D `SE1` streaming beats DRU0 due to per-call prologue latency; on matrices `>= 1 MiB` (e.g., `W1`/`W3`/`W2` on `Qwen2.5-0.5B` and `Wcls` on all models), DRU0 L2 ping-pong lifts effective streaming up to **`10.52 GB/s` raw (`21.0 GB/s` eq-INT8)** (`+6%` to `+13.6%` faster).
- **MMA-accelerated W4A8 group-64 (`c7x_mma_gemm_w4a8_g64_f32`) vs. vector-only W4A8:** A scalar-assisted vector group-64 W4A8 kernel ran at only `1.64 GB/s` (`3.125 ms` on `wcls`) due to short `n_groups = 5` loops and `float16` register spills in `cl7x 1.2.0.STS`. Unpacking tile-major `[N/64][K/64][32][64]` int4 weights on the fly via 5-op zero-borrow `ulong8` SWAR sign-extension (`((((pk & 0x0F) ^ 0x08) | 0x80) - 0x08) ^ 0x80`) straight into MMA `__HWALDB`/`__HWALDAB` with dual `SE1` (weights) + `SE0` (scales) and 4 register-resident `float16` accumulators (zero `y_i32[vocab]` buffer!) gave a **5.1× speedup** on `wcls` (`3.125 ms → 0.54–0.61 ms`) and enabled 151,936-vocab `Qwen2.5-0.5B` to fit comfortably inside 444 KiB L2 SRAM.
- **Keep other coprocessors stopped:** If the parent repo's `ai64-demo` is still running on the board, `C66x 0/1` write to `0x64810000` (inside C7x L2 SRAM) and `ICSSG1 PRU0` streams to `0xAC000000` (the DDR arena). Stop unrelated remoteproc cores before running `c7x-ai`.
- **Scalar `libc.a` `expf()` cost on C71x:** TI CGT's scalar `expf()` takes ~650 cycles/element on C71x silicon (`3.024 ms` for 4,608 SwiGLU elements and `0.55+ ms` for short attention softmax tails). Replacing every `expf()` path (including `<16`-element softmax tails) with a 16-wide Cody-Waite `float16` `vexpf_f16` + 2-step Newton-Raphson `vrecip_f16` (`__recip`) gives `< 5e-7` error and an **89× SwiGLU speedup** (`3.024 ms → 0.034 ms`).
- **1D tile-major MMA vs. 2D strided SE1 on DDR:** For `M = 1` decode, opening `SE1` in 2D strided mode per `64×64` tile tops out at `~4.2–4.4 GB/s` on LPDDR4 (`2.45 ms` for `1×320×32000`). Pre-packing weights into contiguous `[N/64][K/64][64][64]` tile-major order and opening `SE1` **once** as a 1D linear stream (`c7x_mma_gemv_i8_i32_tiled`) lifts `Classifier MMA` to **`9.59 GB/s`** (`1.07 ms`, **93.7% of raw SE0 DDR read ceiling**).
- **Avoid demand DDR misses in vector loops (`SE0`/`SE1` prefetch):** Reading 128 KiB of `wcls_s` or strided `k_cache`/`v_cache` rows via plain pointer dereferences stalls on every 64B L2 miss (`~140` cycles/miss, adding `0.7+ ms` per token). Streaming `w_scale` via 1D `SE1` and `k_cache`/`v_cache` via 2D `SE0`/`SE1` cut attention from `0.549 ms → 0.088 ms` and dequant-argmax from `0.304 ms → 0.109 ms`.
- **Avoid uncached A72 `O_SYNC` `/dev/mem` reads for greedy decode:** Reading 128 KiB of `logits` on the Cortex-A72 across `O_SYNC` `/dev/mem` costs `~2.44 ms/token`. Computing greedy `argmax` directly on C7x and returning it in `ctrl->aux1` removes that entire bottleneck (`2.44 ms → ~0.01 ms`).
- **FP32 reduction order & 1-ULP quantization ties:** Dynamic per-vector `int8` quantization amplifies 1-ULP FP32 differences only when an activation lands within `1e-6` of a `.5` half-integer boundary during a tight logit tie (e.g., `stories15M` `pos=18`, where `" outside"` and `" with"` sit `0.025` apart). With `vexpf_f16` + `vrecip_f16`, both C7x host emulation and live TDA4VM silicon agree 100% and match Karpathy's FP32 `stories15M` reference **40/40 greedy tokens**.
- **`cl7x 1.2.0.STS` `D0` reload mis-scheduling under high vector-register pressure (`c7x_rmsnorm_heads_f32`, `head_size=128`):** When `c7x_rmsnorm_heads_f32` held 16 live `float16` vectors (`w0..w7` + `x0..x7` for Qwen3's 128-element head RMSNorm), `cl7x 1.2.0.STS` spilled 1,300 bytes to the stack and mis-scheduled `ADDD .D2 A11,A0,D0` (advancing the head base pointer by `head_size`) one cycle *before* `VLD16W .D1 *D0(0x80),VB13`, causing head `h` to load `x[h+1][0..15]` instead of `x[h][32..47]`. Disassembling with `dis7x` exposed the mis-scheduled `ADDD`; rewriting `c7x_rmsnorm_heads_f32` as a clean 2-pass 16-wide vector loop (`float16` sum-of-squares pass, then scale pass) eliminated all stack spills and fixed Qwen3 QK-RMSNorm to `max_err = 9.5e-7`. Always watch `cl7x` functions with >12 live 512-bit vectors and verify on real silicon (`c7x_vec_selftest` now covers `head_size=128`).
- **`vexpf_f16` `+Inf` → `vrecip_f16` `NaN` on negative SwiGLU gate outliers (`Qwen3-0.6B`):** In `Qwen3-0.6B`, FFN gate activations `hb` occasionally drop below `-88.7228f`, so `-hb > +88.7228f`. Clamping `vexpf_f16` at `c_hi = +88.72283905f` gave `k = round(88.7228 * log2(e)) = +128`, producing IEEE-754 `+Inf` via `(k + 127) << 23`, and Newton-Raphson `vrecip_f16(1.0 + Inf)` computed `0.0f * (2.0f - Inf * 0.0f) = NaN`! Clamping `c_hi = +87.33654475f` keeps `k <= 126` (`pow2k <= ~8.5e37`, strictly finite), so `1.0f / (1.0f + exp(-hb))` evaluates cleanly to `~0.0f` with zero NaNs and snapped `Qwen3-0.6B` from `0/10` to `10/10` exact greedy match (`cos = 1.0000000`). `c7x_vec_selftest` now explicitly tests `SwiGLU(hb = -200.0f)`.
- **Expanding MSMC SRAM (`4 MiB → 7.625 MiB`) via L3 4 KiB edge page tables:** TDA4VM's 8 MiB MSMC (`0x70000000..0x707FFFFF`) has untouchable ATF firmware at `0x70000000..0x7001FFFF` (128 KiB) and DMSC IPC at `0x707F0000..0x707FFFFF` (64 KiB). Replacing the top/bottom 2 MiB L2 blocks with 512-entry L3 4 KiB page tables (`L3_MSMC_LO`, `L3_MSMC_HI`) lets us safely map `0x70040000..0x707DFFFF` (`7.625 MiB`) while leaving hardware-unmapped safety guard bands at both edges (`0x70020000..0x7003FFFF` and `0x707E0000..0x707EFFFF`). This doubles `SmolLM2-135M` MSMC residency (`2 → 4` layers).
- **1.5 GiB High-DDR Arena (`0x880000000..0x8DFFFFFFF`):** BeagleBone AI-64's 4 GiB LPDDR4 splits into 2 GiB low (`0x80000000..0xFFFFFFFF`) and 2 GiB high (`0x880000000..0x8FFFFFFFF`). Reserving `1.5 GiB` at `0x880000000` (mapped via C7x MMU `L1[34]` + `L1[35]` 1 GiB/2 MiB blocks) leaves all 2 GiB of low 32-bit DMA RAM + 0.5 GiB high RAM (~2.1 GiB total) free for Linux while fitting `Qwen2.5-1.5B-Instruct` (`833 MiB`) and `Qwen3-1.7B` (`928 MiB`) with `seq_len = 2048` — and even two simultaneous models (`0.5B + 1.5B = 1.16 GiB`) for speculative decoding.
- **Long-context (`2048–4096`) INT8 KV cache & RPC chunking:** Per-head-row symmetric INT8 KV (`int8[kv_dim]` + `float32[n_kv_heads]` per position, streamed with 2D `SE0`/`SE1` `__SE_PROMOTE_4X_SIGNEXT`) cuts KV memory & DDR bandwidth `3.76–3.88×` while keeping **10/10 exact greedy parity** (`logits cos = 0.9982–0.9995`) on `Qwen3-0.6B`, `Qwen2.5-1.5B`, and `Qwen3-1.7B`. For `2K–4K` prompts, chunking `arena_prefill_tokens()` at `240` tokens/RPC avoids single-RPC timeouts; beyond `pos ~ 2500`, quadratic attention (`hsum_float16` scalar stack loads per `(head, t)` dot product) becomes the main prefill bottleneck (`144 s` of `158 s` at `3,803` tokens).
- **Speculative Decoding Tradeoff on TDA4VM C71x (`W4A8-g64`):** Running `Qwen2.5-0.5B` drafting for `Qwen2.5-1.5B` (`c7x-ai llama spec`) is 100% lossless (bit-for-bit identical output text via `C7X_LLAMA_REQ_ALL_ARGMAX` + KV rollback), but yields **`6.52 tok/s`** (`K=3`, `46.9%` accept, `2.27 tok/step`) vs **`11.50 tok/s`** standard `1.5B` single-token decode (`0.57×`). Unlike GPUs where verifying `M = K + 1 = 4..6` tokens in one batched GEMM costs `~1.0×` single-token decode latency, our `W4A8-g64` batched kernel must drain the MMA C-bank every `K=64` group (`64`-cycle fence + unpipelined `HWAXFER`/`HWARCV` across `M` rows), so `M=4` verification takes **`254.9 ms`** (`2.94×` single-token `86.8 ms`) plus `92.9 ms` for 3 draft steps. Reaching net speculative speedup on C71x would require either a much smaller draft model (`<= 100M` sharing the exact target vocabulary) or per-channel `W4A8` / `W8A8` verification that accumulates across the entire `K` dimension without per-group C-bank drains.
