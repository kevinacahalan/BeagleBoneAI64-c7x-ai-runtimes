# Yocto Image (`meta-ai64`)

This directory contains a `kas` configuration and the `meta-ai64` layer to build a minimal Poky Linux 6.18 image (`ai64-demo-image`) with the C7x AI runtime pre-installed: `c7x-ai` (`/usr/bin/c7x-ai`), bare-metal C7x firmware (`/lib/firmware/c7x-ai.elf`), and the DDR tensor arena device-tree overlay (`/boot/firmware/overlays/k3-j721e-beagleboneai64-c7x-ai.dtbo`). You do not need `platform/beagle-linux/scripts/build.sh` for a Yocto build.

## Layout

- `kas/ai64-poky.yml` — top-level `kas` config targeting `beaglebone-ai64` / `poky` / `ai64-demo-image`
- `layers/meta-ai64/` — recipes for `c7x-ai`, `c7x-ai.elf`, the DDR arena overlay, kernel patches, `extlinux`, the `sysconf` first-boot service, and USB gadgets
- `sources/`, `downloads/`, `build/`, `sstate-cache/` — generated by `kas-container` (not committed)

## Build

A first build takes roughly **3 hours** on a 16-thread host and needs about **150 GB** of free disk space. From the repository root:

```bash
wget -O kas-container https://raw.githubusercontent.com/siemens/kas/5.5/kas-container
chmod +x kas-container
KAS_BUILD_DIR=platform/yocto/build ./kas-container build platform/yocto/kas/ai64-poky.yml
```

Both `podman` and `docker` work. Set `KAS_CONTAINER_ENGINE=podman` or `KAS_CONTAINER_ENGINE=docker` to choose explicitly (unset, `kas-container` prefers Docker if installed, otherwise Podman). `kas-container build` does not write to an SD card.

## Flash & Run

Write the timestamped `.wic.xz` image to a microSD card (verify `/dev/sdX` with `lsblk` first):

```bash
xz -dc platform/yocto/build/deploy-ti/images/beaglebone-ai64/ai64-demo-image-beaglebone-ai64.rootfs-<timestamp>.wic.xz \
  | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress
```

Boot the board and log in as `root` (no password) over the serial console or SSH (`ssh root@<board>`, using DHCP on Ethernet with Dropbear):

```bash
c7x-ai load c7x-ai.elf && c7x-ai bench all
```

> [!WARNING]
> This is a development image with passwordless `root` login. Set a root password or keep the board on a trusted bench network.

## How It Is Built

- **Base layers & machine:** machine (`beaglebone-ai64`), kernel, and layers come from TI's `kas/poky-wrynose-config.yml` (Poky distro). `yocto/layers/meta-ai64/kas/ti-poky-wrynose-config.yml` embeds a copy of that file with its two templates folded in (recording its source commit) so `kas` does not have to clone `oe-layersetup` from `git.ti.com`.
- **TI Linux 6.18 kernel & U-Boot 2026.01:** `ai64-poky.yml` sets `TI_PREFERRED_BSP = "ti-6_18"`, building TI's `linux-ti-staging` (`6.18.51`) and U-Boot `2026.01`, which sends `RP_MBOX_SHUTDOWN` before stopping remote cores (acknowledged by `c7x-ai.elf`).
- **No `ti-eth-fw-j721e`:** omits TI's J721E EVM CPSW9G firmware (`R5F0_0`); the BeagleBone AI-64 Ethernet port uses the MCU-domain CPSW2G driven directly by Linux.
- **GitHub mirrors:** `ai64-poky.yml` fetches the kernel, U-Boot, `ti-linux-firmware`, and `core-secdev-k3` from TI's GitHub mirrors (`TexasInstruments/...`) because `git.ti.com` intermittently fails requests.
