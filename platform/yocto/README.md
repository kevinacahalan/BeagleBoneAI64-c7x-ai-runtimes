# Yocto Image (`meta-ai64`)

This directory contains a `kas` configuration and the `meta-ai64` layer to build a minimal, self-contained Poky Linux 6.18 image (`ai64-demo-image`) with the C7x AI runtimes pre-installed:

- **Shared base:** bare-metal C7x firmware (`/lib/firmware/c7x-ai.elf`), DDR tensor arena overlay (`/boot/firmware/overlays/k3-j721e-beagleboneai64-c7x-ai.dtbo`), and pre-configured `/boot/firmware/extlinux/extlinux.conf`.
- **Path 1 (Native `.c7m`):** `/usr/bin/c7x-ai` (board lifecycle, benchmarks, `.c7m` chat & OpenAI SSE server).
- **Path 3 (`libc7x` + ONNX EP):** `/usr/lib/c7x-ai/libort-c7x-ep.so`, `/usr/lib/c7x-ai/test_ort_c7x_ep`, `/usr/lib/c7x-ai/test_libc7x`, and all four ONNX verification models in `/usr/share/c7x-ai/models/` (plus `libstdc++`).

You do not need `platform/beagle-linux/scripts/build.sh` or `install-beagle.sh` for a Yocto build (unless you also want to cross-compile `libggml-c7x.so` for Path 2 `llama.cpp`). For a side-by-side comparison with the official BeagleBoard Debian 6.18 workflow, see [`docs/OS_SETUP.md`](../../docs/OS_SETUP.md).

## Layout

- `kas/ai64-poky.yml` — top-level `kas` config targeting `beaglebone-ai64` / `poky` / `ai64-demo-image`
- `layers/meta-ai64/` — recipes for `ai64-demo` (`c7x-ai` + DTBO), `ai64-dsp-fw` (`c7x-ai.elf`), `c7x-ort-ep` (`libc7x` + `ort-c7x-ep` + ONNX models), `ai64-boot` (`extlinux.conf`), `ai64-sysconf`, kernel patches, and `bb-usb-gadgets`
- `sources/`, `downloads/`, `build/` (including `build/sstate-cache/` and `build/deploy-ti/`) — generated by `kas-container` (git-ignored)

## Build

A first build takes roughly **3 hours** on a 16-thread host and needs about **150 GB** of free disk space. From the repository root:

```bash
wget -O kas-container https://raw.githubusercontent.com/siemens/kas/5.5/kas-container
chmod +x kas-container
KAS_BUILD_DIR=platform/yocto/build ./kas-container build platform/yocto/kas/ai64-poky.yml
```

- Both `podman` and `docker` work. Set `KAS_CONTAINER_ENGINE=podman` or `KAS_CONTAINER_ENGINE=docker` to choose explicitly (unset, `kas-container` prefers Docker if installed, otherwise Podman). `kas-container build` does not write to an SD card.
- **Sharing caches across builds:** `layers/meta-ai64/kas/ti-poky-wrynose-config.yml` uses `DL_DIR ?=` and `SSTATE_DIR ?=`, so you can pass `DL_DIR=/path/to/downloads SSTATE_DIR=/path/to/sstate-cache` to reuse an existing Yocto `wrynose` cache (e.g., from `BeagleBoneAI64-linux-zephyr-pru-c7x-c66x-demo`) and finish in minutes.

## Flash & Run

Write the `.wic.xz` image to a microSD card (verify `/dev/sdX` with `lsblk` first):

```bash
xz -dc platform/yocto/build/deploy-ti/images/beaglebone-ai64/ai64-demo-image-beaglebone-ai64.rootfs.wic.xz \
  | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress
```

Boot the board and log in as `root` (no password) over the serial console (`ttyS2`, 115200 8N1) or SSH (`ssh root@<board>`, DHCP on Ethernet with Dropbear):

```bash
# Shared DSP load + Path 1 benchmarks (overlay is already active at boot)
c7x-ai load c7x-ai.elf && c7x-ai bench all

# Path 3: libc7x + ONNX Vision & Audio EP (pure C7x & hybrid C7x+CPU models)
/usr/lib/c7x-ai/test_libc7x
/usr/lib/c7x-ai/test_ort_c7x_ep /usr/share/c7x-ai/models 20
```

To also run **Path 2 (`llama.cpp` + `libggml-c7x.so`)** on the Yocto image, clone unmodified `llama.cpp`, build `libggml-c7x.so` (`./platform/beagle-linux/scripts/build.sh ggml`), cross-compile `llama.cpp` for `aarch64`, and `scp` the plugin and binaries to the board (`libstdc++` is already included in `ai64-demo-image` via `c7x-ort-ep`; see [`docs/OS_SETUP.md`](../../docs/OS_SETUP.md#option-b-yocto-poky-618-setup-platformyocto) for the exact `cmake` and `scp` commands). You can also run `./c7x-ai-beagle/install-beagle.sh` from a bundle on Yocto to install `libggml-c7x.so` or update binaries in place without reflashing.

> [!WARNING]
> This is a development image with passwordless `root` login. Set a root password (`passwd`) or keep the board on a trusted bench network.

## How It Is Built

- **Base layers & machine:** machine (`beaglebone-ai64`), kernel, and layers come from TI's `kas/poky-wrynose-config.yml` (Poky distro). `platform/yocto/layers/meta-ai64/kas/ti-poky-wrynose-config.yml` embeds a copy of that file with its two templates folded in (recording its source commit) so `kas` does not have to clone `oe-layersetup` from `git.ti.com`.
- **TI Linux 6.18 kernel & U-Boot 2026.01:** `platform/yocto/kas/ai64-poky.yml` sets `TI_PREFERRED_BSP = "ti-6_18"`, building TI's `linux-ti-staging` (`6.18.51`) and U-Boot `2026.01`, which sends `RP_MBOX_SHUTDOWN` before stopping remote cores (acknowledged by `c7x-ai.elf`).
- **No `ti-eth-fw-j721e`:** omits TI's J721E EVM CPSW9G firmware (`R5F0_0`); the BeagleBone AI-64 Ethernet port uses the MCU-domain CPSW2G driven directly by Linux.
- **GitHub mirrors:** `platform/yocto/kas/ai64-poky.yml` fetches the kernel, U-Boot, `ti-linux-firmware`, and `core-secdev-k3` from TI's GitHub mirrors (`TexasInstruments/...`) because `git.ti.com` intermittently fails requests.
